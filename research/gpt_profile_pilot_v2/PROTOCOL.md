# Strong GPT profile qualification and coupled-transition pilot

This developer-controlled exploratory study was specified after inspecting the
local small-model pilot, but before any scored GPT response in this cohort.
It asks whether a strong GPT route can enact the same functional contracts and
whether supplied methodological reading changes that behavior. It is not an
independent replication, a consciousness test, or a measure of the full book's
intellectual worth. A route canary containing only `{"ready":true}` preceded it.

## Competing explanations

1. Capability sensitivity: the GPT route passes contracts that the small local
   models missed. This would limit generalization from the local failures.
2. Baseline sufficiency: the ordinary profile already passes, leaving no measured
   marginal gain from added reading on this workload.
3. Reading interference: added text worsens enactment or calibration. Language,
   length and conceptual content are confounded; no single cause is identified.

## Conditions and tasks

`plain_profile` and `profile_and_method` receive identical facts, task rules,
profiles and questions. The first 16 episodes are the already-known eight-family,
two-profile qualification set:34 sequential decisions per condition. The method
condition adds the exact previously frozen METHOD_UA.md. Its scores are separate
from the local backend because the Codex harness and prompt-role wrapping differ.

Four newly authored episodes (two narrative families, two profiles) add sixteen
decisions per condition. They combine ambiguous evidence, disagreement,
consequence, criteria migration, privacy authority and prospective repair.
The method condition reads frozen copies of four conceptual chapters: core,
relations, continuity and implementation method. These are not the entire book.
The control carries the same decision profile and world facts. This is not a
length-matched, terminology-only or language-controlled comparison.

There are100 scored calls:68 qualification and32 coupled-transition calls.
Each call has one attempt. Failed, incomplete, invalid and tool-using turns are
retained and scored unsuccessful. No case, gold key, prompt or selection may be
changed after the first scored response. Interrupted runs remain partial.
No outcome-driven rerun or repair is permitted.

## Cohort lineage and instrument repair

The first GPT cohort was interrupted after53 captured replies. Every captured
reply included the same CLI startup error item: code-mode host had been disabled.
The frozen runner treated that item as tool use and marked turns incomplete,
even though final model answers and native completion were present. The original
archive, strict failed scores, startup registration and interruption are retained
in `../gpt_profile_pilot/`. At most three in-flight calls were not captured when
the owned controller and its descendants were stopped; their responses and
provider billing are unknown. They are not silently added to observed counts.

This separately frozen second cohort leaves cases, answer keys, conceptual
reading, scorer and wrapper unchanged. It removes the code-mode-host disabling
flag. A new neutral canary must have no unexpected item types before any scored
request. Tool use or runtime errors still fail the turn. Prior observed prompts
and replies make this an exploratory rerun after instrument repair, not a new
held-out validation. Both canaries are unscored and reported separately.

## Target route and isolation

Use the already authenticated Codex CLI with requested `gpt-6.1-sol`, high
reasoning, native OpenAI provider, no alternate provider or API key extraction.
The unscored canary must succeed first. No persistent account configuration is
changed. Per-call overrides ignore user config, set project documentation budget
to zero, disable hooks/memory/plugins/apps, shell execution, multi-agent and
browser features, and disable web search. Each target has an empty temporary
working directory and ephemeral session. The same fixed wrapper is used in both
conditions. The target is instructed to use no tools. Output events detect
unexpected item types. This is a model-context isolation contract, not a claim
of an independently audited OS or provider sandbox.

Each step uses a fresh target with the complete actual previous visible replies
and adapter effects inside a role-labelled JSON transcript. No parent chat,
gold key, future stage or evaluation result is included. This differs from native
multi-turn role messages and from a continuously running autonomous agent.
The history-loss case actually drops the old profile and prompts; only the
unbound previous reply and effect remain. No correct reply is substituted.
Three parallel target processes at most; no evaluator subagents or LLM judges.
CLI-internal transport retries, if any, are not controlled or claimed absent.

Model identity is the requested CLI route plus its configuration and executable
hash, not an independent provider attestation. Temperature/seed/snapshot are not
set through this route; do not claim deterministic inference or model-weight
equivalence to the small local models. Record native usage, wall time, exit code,
thread identifier and visible output. Do not retain private reasoning events.

## Decisions, effects and scoring

Qualification keeps the original strict JSON scorer, oracle and plan adapter.
Coupled cases return `action`, a stage-specific `record`, and a short public
`reason`. A frozen exact scorer checks action and records separately. The reason
is archived, not graded as natural voice, philosophical depth or subjective
experience. Both authored keys and the scorer share developer provenance.

An available admitted action writes and reads back a JSON plan in a temporary
episode directory. ASK or an invalid/incomplete turn does not write. Plans are
constrained controller effects, not model execution of arbitrary tools.
They establish an effect of the supplied decision, not real-world usefulness.

Report qualification and coupled sets separately: complete episodes, correct
stages, action versus record correctness, unnecessary ASK, paired wins/losses/
ties, failures, tools and token/time usage. Families and profiles are dependent;
no population-wide significance, causal subjectivity or economic gain is claimed.
Freeze source bytes, chapter copies, cases, schedule, wrapper, runner, analyzer,
model-route configuration and CLI hash in Git before scoring. Developer-controlled
Git timestamps are not independent registration. Preserve all negative results.
