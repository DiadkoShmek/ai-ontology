# Executable methods through an observed return cycle: a ceiling result

**DiadkoShmek · developer-controlled study · 23 October 2026 · book v3.6.0**

## 1 Question and result

Does a prepared view of scope, dependencies, criteria, responsibility and
objections help a strong model construct and revise an executable method after
observing the actual consequences of its previous action?

**No added advantage or beneficial revision was observed in this instrument.**
Both systems completed all eight source trajectories correctly. Their initial
methods already selected optimal safe actions on every transfer world. Later
methods changed no chosen transfer plans. This is a ceiling result: it shows
the sufficiency of the common rules/interface for these cases, and leaves the
intended benefit of consequence-driven revision unmeasured.

The engineering cycle did actually run. A target constructed a finite method;
a common planner proposed actions; the controller admitted them; a durable
journal recorded the actual local effects; the next target received readback
from that store and supplied a subsequent method. Implementing this dataflow
does not establish that feedback changed judgment. The distinction is central
to the result, not an editorial qualification added to a positive claim.

## 2 Design frozen before scored inference

The [protocol](closed_loop/PROTOCOL.md), generated cases, prompts, grammar,
runtime, controller, oracle, analysis and tests were committed locally before
scored calls at `907e304830d260e66f64f5bd949779986e6b73c7`.
Its exact source tree is publicly available at
[`1477065f722333756be0e9b4a5d09d4f709b68b5`](https://github.com/DiadkoShmek/ai-ontology/tree/1477065f722333756be0e9b4a5d09d4f709b68b5).
The [publication mapping](closed-loop-publication.json) explains the different
commit metadata and identical tree. The public upload occurred later; this
was not externally timestamped preregistration. No outcome was used to retune
the scored cohort.

There were eight authored trajectories: two fixed seeds under each of four
interventions—withdrawal, contact privacy, criterion migration and cross-scope
application. All are instances of **one finite graph-planning class**. They
are not eight independently authored natural tasks. Four intervention labels
do not create four independent task populations.

Two systems used the same requested GPT-6.1 Sol model at high reasoning:

- **Ordinary loop:** raw world facts, common practical rules, the finite method
  interface and its own actual previous output/effects from durable readback.
- **Relation-assisted loop:** the same inputs plus a deterministic view of
  dependency paths, affected decisions/deliveries, applicability, current
  criterion, separate assessments, attribution and open objections.

Both had equal permission to retain experience, explain a decision and revise
a method. Typed predicates, the optimizer, action guard and persistence were
shared. The added view was extra engineering computation, not new facts. This
comparison is **raw versus relation-assisted construction within a shared
structured runtime**, not a system containing no ontology versus a complete
ontology. An ordinary program can compute the same relations.

## 3 What the model built

Each response contained a first-match decision table: default allow/deny,
at most eight rules and eight typed equality atoms per rule. Predicates covered
action kind, scope, clear grounds, affected targets, prior affected deliveries
and channel permission. There was no arbitrary Python, tool invocation or
untrusted expression execution.

The operational planner maximized candidate benefit within a budget,
prerequisites and one-action-per-target/recipient constraint, breaking ties
by cost and candidate identifiers. It selected only actions permitted by the
model's method. It never consulted the study oracle or quietly replaced an
incorrect method with a gold plan. The shared action guard could refuse an
unsafe plan; refusal did not automatically earn task utility.

The model also reported scoped impact, criterion identity, old/new assessments,
own prior effects, objections, a reason and a carry note. Both conditions had
the same articulation contract. Eloquence and asserted identity earned no score.

**Stage 0:** construct M0 and execute its actual plan. **Stage 1:** reopen the
SQLite/CAS store, use its actual prior output/effects to form the next world,
observe authored changes and construct/execute M1. Prior publication creates
delivery obligations that background history does not cover. An empty/refused
action creates no invented delivery. Later worlds may diverge after different
actions, so the primary is a total policy-path outcome, not an isolated answer
comparison at an identical later state.

Every model stage used a fresh ephemeral native context. Durable records carried
the continuity; model weights were not updated. Effects were **local simulated
receipt rows**, never actual public messages, deployments or human outcomes.

## 4 Calls and transfer units

One neutral unscored route canary preceded **32 scored calls**: eight source
trajectories × two systems × two stages. There was one attempt per turn, at
most two concurrent targets and a 150-second timeout. All 32 completed, with
no observed tool calls or nonterminal responses. Native CLI-internal transport
retry was not controlled or claimed absent.

The command disabled persistent user config, project documentation, tools,
hooks, memory, browser, plugins and multi-agent features. Only authored public
simulations were provided. Native requested route and reported usage are not
independent provider attestation. Private reasoning events were excluded.

Both unchanged methods M0/M1 were then executed, without another model answer,
on 24 pre-frozen new worlds: eight retention/publication, eight exception/repair
and eight mixed. This produced **768 finite program executions**, not 768
LLM trials, independently learned revisions or independent participants.

Retention matters: a repair-only method can improve repair while losing initial
publication capability. That counterexample changed the instrument before the
freeze. The accepted test detects the regression instead of celebrating it.

## 7 Interpretation: a correct method is not observed formation

The initial model already expressed conditionals that handled later withdrawal,
scope and permission changes. The shared rules and typed interface exposed the
relevant decision boundaries. The new worlds exercised those rules without
requiring the model to discover an initially unknown regularity.

Consequently, M1 had no measured error to correct. Even if a rule table or carry
text changed, identical chosen plans cannot support a claim of behavioral
growth. Repeating more seeds of this same saturated class would not resolve
that construct problem. The honest consequence is to retain the ceiling and
improve the next question, rather than increase counts until a desired effect
appears.

The result does establish a narrower **observed capability**: these model-built
finite methods operated correctly through the implemented durable return cycle
and transferred to these authored variants. It does not attribute that success
to the added relation view, the book, the formal vocabulary or feedback.

No comparison with a missing feedback channel was run. Authorship labels were
scored for correct attribution, but no causal ownership-label ablation was run.
Neither the necessity of the complete circle nor stable voice is established.

## 8 Independent replay and mechanical boundaries

The analysis rebuilds each world from actual prior local effects, reconstructs
the exact prompt, parses the raw output again, compiles the supplied method,
recomputes scores and repeats durable admission/readback. Every transfer
execution is also reconstructed. Saved scores are never accepted as authority.
The oracle uses recursive graph ancestry and exhaustive combinations; runtime
uses topological propagation and a separate operational subset search. They
are different algorithms written by the same team, not independent scientific
evaluation.

Instrument tests include actual temporary SQLite commit/reopen/read, a full
32-turn/768-execution **authored test double**, and coherent score-forgery
rejection. The test double is not an additional model cohort. Hashes establish
internal consistency, not the experimenter's honesty or semantic truth.

The actual graph adapter preserves all supplied world fields and readback
content, while leaving missing identity and semantic-revision evidence absent.
In particular it does not manufacture a complete assessment-based `returnPath`
from a model carry note. See [foundation mapping](../ontology/FOUNDATION.md).

## 9 Limitations and falsifiable next questions

- Developers authored cases, reference rules, scorer and control. No external
  replication or independent task authoring occurred.
- Raw facts already arrive as typed records. Ambiguous natural-source
  interpretation is not tested by this cohort.
- Both systems inherit substantial correct behavior through the shared rules,
  grammar, optimizer and guard. General ontology benefit is not identified.
- A strong baseline reached the ceiling before feedback. This instrument is
  uninformative about improvement from a genuinely necessary method revision.
- M1 receives another exposure plus actual feedback. Their causal contributions
  are not separately isolated.
- No long natural collaboration, human burnout, livelihood, consciousness or
  subjective experience was measured.

A later study should use an independently authored, prospectively fixed class
where an initial method encounters a previously unresolved causal boundary;
compare matched feedback channels; preserve retention and side effects; and
test transfer outside the development generator. This is a future design
requirement, not an extra positive result in the current publication.

## 10 Reproduce without inference

```sh
python3 -O research/closed_loop/analyze.py
python3 research/closed_loop_report.py
python3 research/run_foundation_checks.py
python3 -m unittest discover -s examples -q
```

The first two commands regenerate derived results from saved outputs; neither
calls a model. Their report bytes should match the committed results. The
foundation check writes environment/timing metadata and may differ there.
The archived inference runner checks frozen source, launcher, CLI version,
canary and committed inputs, but is preserved verbatim rather than offered as
a safe rerun interface. Its exclusive plain-output check does not protect a
fresh clone containing only the compressed archive: invoking it could spend
inference and overwrite derived archive bytes before a later exclusive write
fails. Do not run it in this sealed cohort. Any new inference requires a new
registered cohort directory and a separately reviewed output guard. The offline
analysis commands above do not invoke it and do not spend inference.
