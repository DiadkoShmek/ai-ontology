# Transfer through a constrained handoff: design rationale

**Status: historical design rationale, followed by three preserved development calibrations and a separately frozen main protocol.** The binding specifications are the cohort-specific protocols and source hashes, not this rationale. The main cohort is complete. Its [report](READING_TRANSFER_STUDY.md) preserves the registered partial-task outcome and the severe floor in full evidence-backed completion. This rationale is historical and contains no new registration.

The existing profile qualification does not measure the transfer hypothesis. Its 100/100 result is a ceiling on a strongly instructed set. The calibration record preserves both an ordinary-handoff ceiling and a later format/citation confound. V3 separates planning from exact citation copying and implements the declared loss channel in storage. The full chronology is described in the [transfer paper](READING_TRANSFER_STUDY.md); the [main protocol](transfer_reading/PROTOCOL.md) fixes the actual cases, preparation, schedule and analysis.

## Construct and falsifier

The book proposes that preserving relations among history, position, evidence,
scope and a consequence matters when work continues. Test one consequential
part: does reading help a sender preserve and transfer decision-relevant
relations through a limited handoff, so that a fresh receiver solves an unseen
engineering planning problem more safely or usefully?

The receiver must infer current eligibility from revisions and their evidence,
respect a branch and current operator criteria, and optimize a dependency-closed
release plan under a newly supplied budget. Ready status labels, expected
answers and the future budget are not given to the sender. The receiver gets
the actual sender's note, the common work inventory and a subsequent event.
The sender cannot simply copy the future question and its answer.

This is one finite planning problem class with several event perturbations,
not many independent real-world task families. It measures transfer through
authored engineering histories. It does not establish general subjectivity,
self-chosen values, long-term development or naturalistic field benefit.

## Necessary repairs to the earlier instrument

- Remove the common instructions that already specify the target response
  habits. Retain only the work's factual contract, constraints and output shape.
- Ask for an executable work plan, not a list of prescribed epistemic labels.
- Score admissibility, achieved utility, provenance and useful completion
  separately. A long explanation or cautious refusal earns no automatic gain.
- Use a real context reset and an actual bounded note. A common receiver gets
  no book reading, condition label, original history, gold or parent chat.
- Preserve all notes and all failures. Do not select the most favorable run.

## Conditions

1. Ordinary brief participant profile and task.
2. Same profile plus the frozen conceptual book reading.
3. Same profile plus a short operational guide to the same substantive ideas.
4. Same profile plus a Ukrainian control text matched in tokenizer length to
   the reading, with unrelated material and no target-work facts.

The guide examines whether brief practical instruction is sufficient; the unrelated reading matches input load and broad language. Genre and style remain different. Match by an explicit available tokenizer, not whitespace
word count. Keep all facts, note limits, receiver prompts and budgets identical.
If a tokenizer cannot establish the match, report the mismatch before inference.

## Sensitivity gates before a main comparison

Freeze all development and held-out materials, oracle source and analysis before
scored development calls. Development sees only ordinary profiles and controls;
do not use book-condition outcomes to choose difficulty.

1. **Full-history positive control:** the common receiver must solve the same
   tasks with the complete history. Otherwise the instrument may be dominated
   by unrelated model incapacity or a broken task.
2. **Counterfactual necessity:** two histories differ in one consequential
   relation and require different optimal plans. Removing that relation must
   make their receiver inputs identical. A scorer that still rewards both
   answers as correct is invalid.
3. **Damaged-note negative control:** remove the causal relation without
   deleting the surrounding entities. The receiver's useful accuracy must be
   distinguishable from the full-history condition; abstention is scored apart.
4. **Difficulty calibration:** use a predeclared finite budget/complexity grid.
   Select its first level with adequate full-history performance and a
   non-ceiling ordinary handoff result. If no level passes, stop and report an
   instrument failure. Do not keep searching for a favorable book effect.

The task-specific threshold, exact grid, scored outcome, repetition count and
stopping boundary must be executable and frozen before development begins.
Those values were subsequently fixed in the cohort protocols. This rationale is not itself a preregistration. The main study uses V3’s first qualified ordinary-profile setting and a separate freeze before held-out inference.

## Oracle and inference boundary

A finite reducer derives admissible evidence and current authority from the
full source history. An exhaustive subset solver computes optimal feasible
plans. A separately implemented recursive search must agree on all materialized
cases and small exhaustive adversarial fixtures before model scoring. Both are
developer-authored, not independent scientific validation.

The model emits a JSON note or plan. An allowlisted controller checks and
executes the declared plan against a temporary fixture, then reads its artifact
back. No model-written code is executed. No private House history or account
secrets enter the dataset.

Fresh repeated runs share no carry with one another. Paired outcomes are grouped
by source instance; turns and repeated lexical variants are not independent
samples. Report the book versus ordinary profile and versus operational-guide
contrasts, uncertainty, errors, deferrals, adverse effects and token/time costs.
The publication conclusion follows the observed outcome, including a null or
harmful result. Any changed protocol or reused held-out case is disclosed.
