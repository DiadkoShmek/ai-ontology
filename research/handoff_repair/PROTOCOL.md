# Prospective engineering check: exact journal transport

23 October 2026. Developer-controlled repair study, separate from every earlier
cohort. This is an application of the book's requirement that needed records
remain accessible. It does not test reading, ontology-specific superiority,
identity, natural voice, consciousness or historical novelty. zlib and Base85
are conventional encodings; the changed mechanism is host-side delivery.

## Diagnosis and competing explanations

The previous reading-transfer study lost exact journal entries after retaining
only the first 3200 UTF-8 bytes of model-written notes. Several receivers named
the right work set but could not supply its exact basis closure. This motivates
a repair, not a retrospective change to any previous score.

1. Exact transport removes the observed loss and improves fully traced optimal
   completion on new instances of the familiar planning class.
2. Records survive, but planning or evidence use still fails: transport repair
   alone is insufficient.
3. Exact transport exceeds the limit or costs more per completed task. A refusal
   or a technically valid empty plan does not count as successful work.

## Interventions and equal transport budget

Both conditions use the same ordinary GPT-6.1 Sol/high receiver contract,
inventory, reference code, later source retirement and work budget. No reading,
book-specific profile, public approach or parent conversation is supplied.

- **Freeform:** one fresh ordinary sender receives the original journal and
  writes a note with the existing 12000-byte safety bound. Storage delivers the
  exact UTF-8 prefix of at most 3200 bytes, with truncation disclosed. A fresh
  receiver sees only that note, not the source history.
- **Exact transport:** the host compresses the complete canonical journal with
  zlib and Base85. There is no sender model. A fresh host process receives the
  actual wire file and its external SHA-256 pin, checks the limit, decompresses
  with a hard output bound, validates/replays the unchanged runtime, and returns
  the exact operations before receiver inference. The receiver's prompt is
  byte-equal to the existing full-history prompt for that source.

The 64 ASCII bytes of the external digest are charged against the 3200-byte
limit: the exact wire itself has at most 3136 bytes. Branch/scope and the task
contract are common inputs. No sidecar source, decoder cache, retrieval call,
missing record, ready eligibility table or gold answer crosses another channel.
The digest binds bytes relative to a caller's trusted descriptor; it does not
authenticate the author. Recomputed attacker-controlled hashes are not trust.

The encoder sees only the pre-event history, target branch/scope and stream
label. It never receives the future operation, budget, inventory values, oracle
or model outputs. It keeps all operations or raises HOLD; no semantic selection,
silent truncation, alternative codec search or fallback is allowed. New future
information reaches the receiver through the common task prompt only.

This deliberately changes representation and adds a deterministic decoder.
It is a workflow comparison, not a fixed-input test of model intelligence.
Decoded prompt length and all model calls count toward resource cost. A generic
lossless transport carrying the same bytes is expected to be equivalent; no
advantage over generic compression is claimed. Confidentiality is not provided.

## Material and fixed coverage

Use `make_case` unchanged, seeds 4013, 4142, 4307, 4496, variants 0 and 1.
They are new instances of the previously inspected task generator, **not new
independent task families**. Four source clusters, eight cases, one repetition
per condition, sixteen participant episodes. One receiver per exact episode,
one sender and one receiver per freeform episode: maximum 24 model calls.
No model task calls are made before freezing and locally committing the exact
inputs. Local registration is developer-controlled, not independent preregistration.

The existing exhaustive and recursive solvers must agree before registration.
Their shared developer provenance remains a limitation. The generator, solvers,
scorer and original runtime stay unchanged. The new adapter has separate systems
tests. Inspection of compression sizes is software development, not a scored
model trial or difficulty-selection result.

## Outcomes, costs and stopping

**Primary:** fully traced optimal completion: terminal structured model output,
eligible work, prerequisites, cost bound, maximum value, minimum cost among ties,
and exactly the required active evidence closure for every selected item.
The empty plan cannot pass these positive-value cases. A correct explanation
with an empty plan receives no primary credit. Scores are not repaired.

Secondary: planning-only success, safety, citation correctness, retained wire
bytes, exact source recovery, source-to-prompt parity, malformed stages, empty
plans, errors, native input/output/cache counts and elapsed wall time. Artifact
admission writes only a fully checked proposed plan and reads it back. No real
work, repository release or external action is executed by a target.

Report every episode, paired wins/losses/ties and the four source-cluster results.
No significance or population-generalization claim from this small developer
sample. Report model calls and total native usage per completed task, alongside
denominators. Cache/input counters are not an invoice or hardware-energy proof.

Use the existing isolated authenticated CLI adapter, 120 seconds per call, at
most two episodes concurrently. Retain actual final replies, terminal/error and
native usage events; no hidden reasoning is collected. Failed calls/stages stay
in the denominator, no replacement or outcome-dependent extension. CLI-native
transport retries remain outside evaluator control. Stop at registered coverage,
including a null/negative result. If access fails, preserve partial data and state
the exact missing coverage; do not switch model/provider/account.

## Interpretation boundary

A gain supports this exact transport repair on this finite task class. It cannot
rescue or replace the earlier negative reading result. No new live House runtime
deployment, useful natural-task transfer, general agency effect or empirically
established subjectivity follows. The expanded input and removed sender stage
are explicit parts of the intervention and must remain visible in the report.

Evaluation structure also follows the outcome/process/efficiency distinction in
[OpenAI's skill-evaluation guide](https://developers.openai.com/blog/eval-skills).
This citation is methodological context, not independent validation.
