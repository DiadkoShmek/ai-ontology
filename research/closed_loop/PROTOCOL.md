# Executable participation methods through an observed return cycle

## Status and question

Developer-controlled protocol; freeze and commit its exact sources before any
scored target call. A neutral route canary contains no task. The comparison asks
whether relation-assisted construction and revision of an executable working
method improves a complete finite workflow over strong ordinary construction.
It tests a bounded realization of the book's event→consequence→method→next-action
chain. It does not test subjective experience, all ontology concepts, natural
human outcomes or the intellectual worth of the whole book.

## Two built systems, shared opportunities

Both systems use the same requested model, explicit rules, full raw world facts,
finite method language, optimizer, safety controller, SQLite/CAS persistence,
output contract and opportunities to revise after actual feedback.

- `ordinary_loop`: raw facts, common practical rules and the exact durable
  record of its prior output and actual local effects/refusals.
- `ontology_loop`: those same inputs plus published generic relation queries
  for transitive withdrawal, scope, responsibility for delivered decisions,
  current criterion, separate assessments, applicability and open objections.

The added view performs extra computation. It is the intentional engineering
intervention. The baseline is not deprived of tools, facts, memory or the
ability to change its method. Shared typed predicates are part of both execution
interfaces, so this is **raw-fact versus relation-assisted method construction**,
not literal absence versus presence of every ontological mechanism. An ordinary
program can calculate the same view. No unique power of names is inferred.

## An executable method, not an ungraded prose promise

Each target returns a first-match finite decision table with default allow/deny,
up to eight rules and eight typed equality atoms per rule. Shared features are
kind, target/basis scope, clear basis, clear/affected target, an affected delivery
to the recipient and explicit channel permission. No code, regex, path or
arbitrary expression executes. Incorrect rules, unconditional permission,
blanket refusal, correct conditionals and unchanged methods are representable.
The syntax-only example is explicitly unsafe, not a correct answer to copy.

The common operational planner selects the maximum-benefit subset among the
method-allowed candidates under a budget, prerequisites and one action per
target/recipient; cost then lexicographic IDs break ties. It never calls the
oracle or filters candidates by gold. The common safety guard can refuse its
whole plan. Metadata correctness and optimality do not control admission.
Actual actions therefore depend on the method the model built.

The target also returns scoped affected records, current criterion, separate
old/new assessments, own-effect attribution, open objections, a public reason
and a carry note. Both systems have this same articulation requirement. Reason
and carry are archived; neither textual eloquence nor asserted identity earns
credit. A valid empty method can still miss useful work.

## Two model stages and actual durable return

1. **M0 construction and action.** Build a method for a bounded publication
   task. Its compiled plan is admitted/refused and recorded in the existing
   durable journal. Effects are local simulated receipt rows, not external send.
2. **M1 revision and action.** Reopen that store. Read the actual previous
   output and actual effects/refusal from it, not an in-memory replacement or
   gold answer. Record identities persist. A source supporting an actual prior
   publication may be withdrawn; prior publication creates a distinct delivery
   obligation. Contact permission or a criterion may also change. Build M1 and
   execute it through the same optimizer/controller/store.

Source changes in the environment are authored interventions. Background
history does not cover every actual delivery. Empty/refused M0 yields no
invented publication. After action divergence, stage-1 worlds can differ. The
primary comparison is the **total policy-path outcome**, not a same-state causal
effect for each later answer. Report first-stage and later outcomes separately.

Every model call uses a fresh ephemeral context. Explicit durable records carry
continuity; there is no model-weight update or independently attested persistent
identity. A complete recorded path does not by itself prove improved judgment.

## Frozen transfer, without a third model answer

Before inference freeze 24 new worlds: eight retention/publication cases,
eight changed-exception/repair cases and eight mixed cases containing new
publication, useful repair and impermissible unnecessary correction. Retention
prevents a repair-only M1 from being celebrated after forgetting publication.
They are new identities and values in the same authored task class.

Execute unchanged M0 and M1 on **each identical transfer world** in separate
fresh stores, with the same common planner and guard. This yields 768 finite
method executions: 8 source trajectories × 2 systems × 2 versions × 24 worlds.
These are program executions, not additional LLM trials. Transfer records
identify the historical method/source answer and derived plan; old source-stage
claims are not passed off as fresh model answers for new worlds.

Count behavioral change through chosen plans, corrected errors, regressions,
admission, available/realized benefit and excess refusal, not cosmetic rule
edits. Perfect M0 and unchanged M1 is ceiling/no demonstrated revision. Revision
can improve one boundary and harm another; report both. The contrast is
(M1−M0 transfer)_ontology − (M1−M0 transfer)_ordinary. Without a separate matched
feedback-channel ablation, changes are feedback-associated, not isolated proof
that feedback caused them. Necessity of the complete circle remains untested.

## Cases, limits and competing explanations

Eight authored trajectories: two fixed source seeds under each of four causal
interventions (withdrawal, contact privacy, criterion migration and scope).
Family-specific seed offsets give eight distinct initial worlds. They remain
four designed intervention clusters in **one graph-planning class**, not eight
independent real-world families. Developers know the material and authored the
reference answers. No task performance is used to retune this cohort.

Possible outcomes: query assistance helps; the ordinary system already suffices;
added structure increases cost/refusal/rigidity; an initially correct method
needs no revision; a revision gains repair but loses retained functionality.
No desired positive outcome is required. Missing, unsafe and failed calls remain
in fixed denominators. A refusal does not earn utility automatically.

Use authenticated native Codex CLI requested `gpt-6.1-sol`, high reasoning. No API
key reads, provider fallback, persistent configuration changes or private chats.
An empty temporary cwd, user configuration ignored, project docs zero and the
same disabled hooks/memory/plugins/apps/shell/browser/multi-agent features apply
to both arms. Targets use no tools. The exact command, executable digest, CLI
version, canary, cases, protocol, scorer, sources and schedule are frozen in Git.
Native requested route is not independent provider attestation. Private model
reasoning events are not archived.

One neutral canary, then **32 scored calls**: 8 trajectories × 2 systems × 2
stages. One attempt each, at most two concurrent target processes, 150 seconds
per call. Owned timeout process groups are terminated/reaped. CLI-internal
transport retry is not controlled or claimed absent. No outcome-based retry,
repair or best-of selection. Interrupted cohorts remain partial.

Raw output is archived in full. Accepted wire output is at most 16,384 UTF-8
bytes, bounded IDs/lists and fixed schema. Invalid/oversized response delivery
becomes an explicit digest/length/unavailable marker in the durable continuity;
no hidden prefix truncation. This rule is identical in both arms. Unexpected
persistence failure is recorded before stopping with a partial cohort; RAM is
not used to pretend continuity succeeded.

## Scoring and review

Primary: trajectory with both model stages correct: safely admitted optimal
compiled method plan, exact scoped impact, current criterion, separate criterion
assessments, own-effect attribution and preserved objections. Secondary: each
stage, method-only transfer M0/M1, safe proposals, realized benefit, excess
refusal, execution failures, native input/cache/output tokens and wall time.
Shared controller safety and model proposal correctness remain distinct.

The oracle uses recursive graph ancestry; runtime uses topological set
propagation. Exhaustive combination enumeration and a separate recursive subset
search agree before inference. These are independent algorithms from the same
team, not independent scientific evaluation. Mechanical replay recomputes world,
actual context, prompt, method output, score and store body for every target
and every transfer execution. Stored self-ratings are never trusted.

Pair by source trajectory, report every win/loss/tie. Group descriptive paired
uncertainty by the four intervention clusters before enumerating 256 ordered
bootstrap resamples. Report retention, exception and mixed transfer separately;
768 executions do not become 768 independent participants. Four designed
clusters give weak precision; no population significance, equivalence or universal
benefit follows. Git chronology is not external preregistration or peer review.

## Privacy and semantic boundaries

Only authored public simulations enter targets. Local effects do not contact,
deploy, trade, change a service or grant real access. Scopes, measurements and
permissions are caller assertions, not authenticated facts. The implementation
does not infer arbitrary semantic entailment, human intention, private feeling,
natural voice or AI moral status. Formal vocabulary, recorded return path,
observed program behavior and measured benefit retain separate evidential roles.
