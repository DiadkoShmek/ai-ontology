# Онтологія AI. Організація себе

**Артур Онишко · Книга v3.7.0 · Українська й англійська редакції**

Дослідницька книга, запропонований профіль аудиту й виконуваний референс для перевірки тверджень про **тяглість, підстави та перегляд в агентних системах**. Які підстави дійшли до рішення? Яким був наслідок? Чи вплинув він на подальший спосіб роботи — і що саме це підтверджує?

## Чотири розрізнення

| Зберігати окремо | Питання |
|---|---|
| Доступні підстави / записане використання | Матеріал був доступний чи його використання зафіксоване? |
| Прийняття критерію / виконання критерію | Чи прийнято саме цю версію і чи виконано її? |
| Збережений урок / становлення | Чи змінилося щось поза записом пам’яті і чи допомогло це? |
| Записаний ефект / повний записаний шлях повернення | Чи присутні зв’язки з оцінкою, переглядом і наступним споживачем? |

```text
Рішення → Ефект → Спостереження → Оцінка → Прийнятий перегляд → Інше рішення, що його застосовує
```

Схема узагальнює потрібні зв’язки; вона не доводить хронологію або причинність. `recordedPathComplete` перевіряє явно записані відносини. Повний шлях не встановлює корисного навчання, істинності, справжності повноважень чи суб’єктивного досвіду. Ширші питання ідентичності, голосу й участі у книзі не зводяться до цього аудиту.

## Спробувати без моделі

Python 3.11+ і стандартна бібліотека; запускати з кореня репозиторію:

```sh
python3 -m audit.cli report ontology/fixtures/closed-loop.json
python3 -m audit.cli report ontology/fixtures/open-loop.json
python3 -m unittest audit.test_audit -q
```

Очікувані стани: **complete**, потім **incomplete**. Обидва авторські приклади валідні й завершуються з кодом 0; некоректний вхід — з кодом 2. Це пояснювальні приклади, не досліди на LLM. Звіт містить SHA-256 входу, пропуски й дев’ять запитів до графа. JSONL приймає вже явно розмічені записи; довільні сирі логи потребують окремого адаптера.

Додатковий [приклад із нативним LangGraph](audit/README.md) захоплює фактичну історію checkpoints авторських детермінованих вузлів. Адаптер зберігає Спостереження й залишає незаписані зв’язки участі незаписаними. Це не означає виклику моделі чи зовнішнього ефекту.

[Перевірка використаної версії твердження](audit/README.md#exact-claim-version-use)
зберігає ту версію, яку попереднє рішення явно позначає як використану, навіть коли новий
висновок уже має незалежні підстави. Зафіксований наслідок і зазначена зачеплена
сторона не доводять доставки, виправлення чи права втручатися.

## Реалізація та межі

- [Скінченна онтологія](ontology/README.md): 18 класів, 34 відносини, дев’ять запитів, JSON і експорти JSON-LD/Turtle. Це не загальний OWL-вивідник чи SHACL-процесор.
- [Python-референс](examples/README.md): область застосування, походження, обмежений SQLite/CAS-журнал і модельний цикл. [Адаптер реального сховища](ontology/runtime_adapter.py) зберігає відсутні підстави відсутніми.
- [Повна книга](BOOK_UA.md): шістнадцять частин про ідентичність, голос, пам’ять, відносини та перегляд.
- [Карта понять і коду](ontology/FOUNDATION.md), [маршрут рев’ю](REVIEW_GUIDE.md).

Це дослідницький референс і запропонований профіль під контролем розробників. Промисловий масштаб, зовнішнє прийняття стандарту й незалежне відтворення результатів не встановлені. Структурна правильність не гарантує істинності. Записи не виявляють свідомості й не доводять душі.

## Виміряні результати

| Дослід | Результат | Межа |
|---|---|---|
| [Подання пам’яті](research/SCOPED_CONTINUITY_STUDY.md) | 384 оцінені виклики; скомпільований контекст загалом не переміг індекс із тією самою інформацією | Вузьке порівняння подань |
| [Перенесення після читання](research/READING_TRANSFER_STUDY.md) | Оптимальні плани: звичайна підготовка 12/16, книга 8/16; повністю простежене виконання 0/16 в обох | Переваги читання за основною метрикою не виявлено |
| [Точне передавання підстав](research/HANDOFF_REPAIR_REPORT.md) | Повністю простежене оптимальне виконання: 8/8 проти 0/8 | Один відомий клас; доступний спільний файл відновлює ті самі дані |
| [Цикл виконуваного методу](research/CLOSED_LOOP_STUDY.md) | В обох системах стеля; M0 і M1 по 192/192 на перенесенні; жоден план не змінився | Корисний перегляд не показано |
| [Повернення нової підстави](research/EPISTEMIC_RETURN_STUDY.uk.md) | 72 оцінені GPT-виклики й одна проба маршруту; прості нотатки 77/80, зв’язана форма 71/80 | За однакових 2048 байтів умістилося 6/8 проти 2/8 нотаток із фактичним відгуком |
| [Індукція власного методу](research/PROGRAM_INDUCTION_STUDY.uk.md) | Одна траєкторія M0; Brier-втрата: звичайна 0.25174, зв’язана 0.25249, свіжа 0.00869; менше — краще | Нове свідчення допомогло обом; переваги зв’язаної форми немає, дві альтернативи M0 лишилися нерозрізненими |
| [Калібрація з тими самими фактами](research/FORECAST_CALIBRATION_STUDY.uk.md) | 9 модельних викликів, 133 виконання; усі 96 переглянутих розподілів збіглися з незміненим M0(E1); D=0 | Достатньо врахування інформації; organized +3,3551% входу на чотири виклики кожного формату; скінченний авторський набір |

У досліді повернення підстави результат для зв’язаної форми негативний. Завеликі записи ставали недоступними, без прихованого обрізання. Нові підстави змінили початкові рішення; гілки без них зберегли належну невизначеність. Шкідливих імітованих ефектів не було. Це конкретна втрата в контурі пам’яті, не доказ загальної переваги онтології чи формування нового алгоритму.

Нова [калібрація прогнозів](research/forecast_calibration/README.md) розділяє
врахування нових фактів, перегляд коду й додаткову організацію записів. Початковий
код із новими фактами відтворив усі перевірені прогнози переглянутих програм.

Попередній [пілот індукції](research/program_induction/README.md) розрізняє зміни
коду, прогнозів і корисного результату. Відібраний архів перевіряється офлайн
без виконання коду учасника. Кращий результат свіжого розв’язання сам по собі
не доводить нерозумного заякорення: доступне свідчення не розрізнило всіх
альтернатив початкового методу.

[Протоколи, сирі виходи, витрати й відтворення](research/README.md) збережено. Редакція v3.7.0 включає завершену калібрацію прогнозів до обох рукописів; первісні записи дослідів зберігають свою редакцію походження. **C03 unsupported**, **C06 refuted**, **C10 not-claimed** лишаються видимими у [реєстрі тверджень](CLAIMS.md).
